## 왜 질문받는 방식이었나

팀 프로젝트 RePlant Market의 배송 기능에는 외부 택배사가 필요했고, 실제 택배사 API 대신 **모의 택배사**를 직접 만들기로 했습니다. 머릿속에 있던 건 "당근 택배를 모방한다", "수거 전에는 취소할 수 있다", "서버가 꺼져도 이벤트가 유실되면 안 된다" 정도였습니다.

이 상태에서 바로 "만들어 줘"라고 하면 AI가 빈칸을 스스로 채웁니다. 그래서 반대로 **AI가 정해야 할 것을 묻고, 나는 결정만 하는** 방식을 택했습니다.

## 진행 방식

`/grill-me` 스킬은 결정할 것을 트리처럼 펼쳐 라운드마다 질문하고, 각 질문에 AI의 추천안을 함께 붙입니다. 답이 짧아도 추천안이 기본값 역할을 해서 결정이 빠지지 않습니다.

첫 메시지에는 아는 것만 적었습니다.

> "일단커밋이라는 팀안에서 식물 중고거래 사이트를 만들고 있는데 이 사이에 택배를 보낼 가짜 택배사 하나가 필요해. 초기 기획으로는 간단하게 당근 택배를 모방해서 만들거야. … 서버가 꺼져서 이벤트 유실이 되지 않게끔"

## 라운드별로 정해진 것

| 라운드 | 결정한 것 |
| --- | --- |
| 1 | 멱등키 방향, 상태 알림 방식(웹훅/polling), 자동 진행 방식, 수거 후 취소, 스택 |
| 2 | 배포 환경 충돌, 키 생성 주체·형식, 진행 간격, 웹훅 순서 역전, 재시도 상한 |
| 3 | 웹훅 순서 보장, 취소 웹훅 여부, 엔드포인트 경로, 서비스 간 인증, 송장 형식 |
| 4 | URL에 넣을 ID, 팀 공통 응답 형식, 배포 방식, 실패(DEAD) 처리 |
| 5 | 멱등키를 헤더로 둘지 URL로 둘지 |
| 6 | 로컬 개발 시 웹훅 수신 방법 |

몇 가지 결정은 이렇게 내려졌습니다.

- **멱등키는 헤더로** — "stripe처럼 헤더로 빼고 … courierOrderNo는 url에 붙이지마"라고 답해, 서버가 만든 `shipment-yyyyMMdd-NNNNNN`을 `Idempotency-Key` 헤더로 보내고 URL에는 송장번호만 쓰기로 했습니다.
- **응답 형식은 팀 서버에 맞춤** — 팀 저장소 링크를 주자 AI가 Spring 서버의 `ApiResponse`를 직접 읽고 같은 형식으로 맞췄습니다.
- **배포 환경 변경** — "서버는 vercel 써도 될거같은데? db는 sqlite로 가자"고 답했는데, AI가 서버리스에서는 SQLite 파일이 남지 않고 상시 작업을 돌릴 수 없다고 짚었습니다. 다음 라운드에서 배포 위치를 바꿨습니다.

6라운드가 끝나고 정리된 내용을 확인한 뒤 "맞아 시작해줘."라고 보내 구현을 시작했습니다. 첫 구현은 테스트 21개와 Docker 컨테이너 E2E까지 확인된 상태로 나왔습니다.

## 프롬프트가 명세서로 바뀌다

기획이 끝나고 기능을 추가할 때는 프롬프트 모양이 달라졌습니다. 웹훅 재전송을 추가할 때의 요청은 이랬습니다.

> "JustCommit 서버(Replant)로 보내는 배송 상태 웹훅에 재전송을 추가해 줘. … 2xx 성공 / 4xx 재전송하지 않음 / 연결 실패, 타임아웃(5초), 5xx: 재전송 / 1분 → 5분 → 30분 → 2시간 → 6시간 (최대 5번) … 확인 방법: JustCommit 서버를 끈 상태에서 배송을 진행 → 재전송 로그 확인 → 서버를 켜면 다음 재전송에서 반영되는지 확인"

**배경 → 할 일 → 확인 방법 → 보고 형식.** 확인 방법을 함께 주니 AI가 구현에서 멈추지 않고, 수신 서버를 실제로 껐다 켜며 재전송이 반영되는 것을 재현했습니다.

검증만 요청할 때는 범위를 좁혔습니다. "배송 취소 API가 아래 동작을 모두 지키는지 확인하고, 다른 부분만 고쳐 줘."라고 하자, AI는 코드를 바꾸지 않고 경합 시나리오를 테스트 10개로 고정했습니다.

## AI를 그대로 믿지 않은 지점

- **보고 규칙** — 보고를 설계 / 작성 / 로컬 검증 / 배포 / 운영 검증으로 나누고, 하지 않은 단계는 "미실행"으로 적게 했습니다. "다 했습니다"와 "로컬에서만 확인했습니다"를 구분하기 위해서입니다.
- **승인 게이트** — 커밋과 push는 올라갈 파일 목록을 확인하고 승인한 뒤에만 하게 했습니다.
- **빠뜨린 것 지적** — 첫 구현에 작업 규칙 문서가 없어 "agent.md는 없어?"라고 묻자, AI가 AGENTS.md와 운영·미결 문서를 만들었습니다.
- **번복** — 시각 형식에서 시간대를 빼는 변경을 테스트부터 구현했다가, 시간대를 붙여 보내기로 결정이 바뀌어 "이전으로 롤백해줘"로 되돌렸습니다. 커밋 전이라 이력이 남지 않았습니다.

## 배운 점

- 요구사항이 흐릿할 때는 AI에게 답을 시키기보다 **질문을 시키는 편**이 빈칸을 덜 남긴다.
- 추천안이 붙은 질문에는 짧게 답해도 된다. 사람의 일은 결정이다.
- 구현을 맡길수록 프롬프트에 **확인 방법**이 들어가야 한다. 그래야 결과를 믿을 수 있다.
- AI의 보고는 "무엇을 했고 무엇을 안 했는지"로 나눠 받아야 실제 상태를 알 수 있다.
