## 상황

Calainder는 사용자가 입력한 텍스트나 이미지에서 AI가 일정 정보를 추출해 Google Calendar에 등록합니다. 날짜가 명시된 입력은 잘 처리됐지만, **"50분 뒤", "4시간 뒤"** 처럼 상대적인 표현은 잘못된 날짜나 시간으로 해석되는 경우가 있었습니다. AWS EC2에 배포한 뒤 저녁 8시 55분(KST)에 "4시간 뒤"를 넣었더니, 다음 날 0시 55분이 아니라 같은 날 0시 55분으로 초안이 나왔습니다.

## 원인

상대시간을 계산하려면 AI가 **"지금이 언제인지"** 를 정확히 알아야 합니다. EC2에서 `date`·`timedatectl`로 확인해 보니 서버 시간이 UTC였고, Docker 컨테이너도 UTC였습니다. 프롬프트에 넣는 현재 시각을 서버 시간으로 만들고 있어 기준점이 9시간 어긋나 있었습니다. 또 프롬프트 구조가 기능마다 흩어져 있어, 종료 시각처럼 시작 시각에서 파생되는 값의 계산 규칙을 한곳에서 관리하지 못했습니다.

## 해결

1. **KST 기준 현재 시각 명시** — 서버 시간대에 기대지 않고 요청마다 `Asia/Seoul` 기준 현재 시각을 계산해 프롬프트에 넣어, 상대시간 계산의 기준점을 고정
2. **공통 프롬프트 분리** — 기능마다 흩어져 있던 프롬프트에서 공통 규칙을 분리해 한 곳에서 관리하고, 종료 날짜 계산 규칙을 예시와 함께 명시
3. **모델 교체** — 기준 시각을 고쳐 다시 배포한 뒤에도 결과가 틀려, 모델을 `gpt-4o-mini`에서 `gpt-4.1-mini`로 바꿨습니다. 바꾼 뒤 배포 서버에서 상대시간 일정이 맞게 나오는 것을 직접 확인했습니다.

"N시간 뒤·N분 뒤"를 서버가 정규식으로 찾아 계산해 덮어쓰는 방법도 검토했지만, 모델 교체 뒤 결과가 맞게 나와 넣지 않았습니다. 상대시간 계산은 여전히 모델에 맡기고 있고 자동 회귀 테스트도 없어, 날짜가 넘어가는 경계에서 다시 틀릴 수 있습니다.

함께 진행한 관련 개선도 있습니다.

- 한 문장에 여러 일정이 있으면 AI 응답을 단일 객체에서 **일정 배열**로 확장해 여러 일정 카드로 분리 (`release/v1.4.0`)
- AI 프롬프트 구조화 (`release/v1.2.2`)

## 배운 점

- LLM 기반 기능은 **프롬프트 설계와 검증이 곧 품질**이다.
- 모델이 스스로 알 수 없는 정보(현재 시각, 시간대)는 추측하게 두지 말고 입력으로 명시해야 한다.
- 규칙만 나열하기보다 예시를 함께 주면 결과가 훨씬 안정적이다.
