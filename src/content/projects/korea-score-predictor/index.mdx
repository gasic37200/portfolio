## 문제와 해결 방향

> **문제:** 매장 고객은 빠르게 이벤트에 참여해야 하고, 운영자는 상대팀과 마감 시간을 자주 바꿀 수 있어야 하며, 휴대폰 번호는 안전하게 처리되어야 한다.
>
> **해결:** QR 진입용 모바일 폼, 관리자 경기 관리 화면, 서버 사이드 개인정보 처리, 경기별 중복 참여 제약을 하나의 MVP로 구성했다.

## 내 역할과 핵심 기여

- **중복 참여** — 같은 번호가 같은 경기에는 한 번만, 다른 경기에는 다시 참여하도록 `match_id + phone_hash` 유니크 제약으로 제한했다([cfb088a](https://github.com/gasic37200/korea-score-predictor/commit/cfb088a))
- **개인정보** — 번호를 해시(비교)·마스킹(표시)·암호화(연락)로 나눠, 원본을 복호화하는 지점을 당첨자 CSV export 한 곳으로 줄였다([#1](https://github.com/gasic37200/korea-score-predictor/pull/1), [72acb55](https://github.com/gasic37200/korea-score-predictor/commit/72acb55))
- **관리자 운영** — 상대팀·마감 시간이 당일에 바뀌어도 seed를 고치지 않고 관리자가 경기 추가·수정·표시/숨김·실제 결과 입력을 직접 하도록 했다. 관리자 화면은 `ADMIN_PASSWORD_HASH` 기반 로그인으로 막았다([#1](https://github.com/gasic37200/korea-score-predictor/pull/1), [039f1a1](https://github.com/gasic37200/korea-score-predictor/commit/039f1a1))

## 아키텍처

**QR 접속 → 이벤트 폼 → Server Action 검증 → Supabase 저장 → 결과 집계 → 관리자 운영**

| 경로 | 역할 |
| --- | --- |
| `/event` | 사용자 입력과 경기 스코어 예측 제출 |
| `/result` | 경기별 참여자 수와 스코어 분포 |
| `/admin/matches` | 경기 추가, 수정, 표시/숨김, 실제 결과 입력 |
| `/admin/export` | 실제 결과와 일치한 당첨자 CSV export |

- 민감한 로직은 Server Action과 server-only helper에서만 처리했다
- service role key·해시 secret·암호화 key는 서버 환경 변수로만 쓰고 브라우저로 전달하지 않았다
- 제출 가능 여부는 클라이언트가 보낸 값이 아니라 서버가 다시 조회한 열린 경기와 마감 시간으로 판단했다

## 주요 구현

1. **서버 기준 제출 검증** — 클라이언트가 보낸 경기 정보를 믿지 않고 서버가 열린 경기와 마감 시간을 다시 조회해, 마감이 지난 경기나 숨긴 경기에 예측이 들어오지 않게 했다
2. **부분 저장 방지** — 예측 저장이 실패하면 직전에 만든 참여자 row를 삭제해, 참여만 남고 예측이 없는 데이터가 생기지 않게 했다
3. **한 번에 한 경기만 노출** — 새 경기를 표시하면 같은 이벤트의 나머지 경기를 자동으로 숨겨, 매장의 QR이 항상 한 경기만 가리키게 했다
4. **모바일 입력** — 번호 자동 포맷, 제출 실패 시 입력값 유지, 마감 카운트다운, 마감 후 제출 버튼 비활성화로 다시 입력하는 일을 줄이고 마감 여부를 바로 알 수 있게 했다

## 회고

상대팀이 당일에 바뀌는 이벤트에서는 개발자가 seed를 고치는 구조가 맞지 않았습니다. 운영자가 직접 바꿀 수 있는 관리 화면을 만들면서 "실제로 운영 가능한 MVP"가 무엇인지 배웠습니다. 중복 참여 기준을 처음에는 이벤트 단위로 잡았다가 경기 단위로 바꾸면서, 제약 조건은 운영 정책을 코드로 옮긴 것이라는 점도 배웠습니다.

배포에서도 한 번 막혔습니다. PR을 만들려고 원격 `main`에 빈 기준 커밋(`chore: initialize repository`)만 올려 둔 상태로 Vercel 프로젝트를 연결했고, 사이트가 404였습니다. PR [#1](https://github.com/gasic37200/korea-score-predictor/pull/1)을 병합하고 재배포용 커밋(`4e9c77a`)을 올린 뒤에도 배포 로그는 빌드 단계가 비어 있는 채(`Builds . [0ms]`) Error로 끝났습니다. 빈 저장소 상태로 연결해 Next.js 프로젝트로 감지되지 않은 것을 원인으로 보고 Framework Preset 설정을 짚었습니다. 그 뒤로는 배포를 연결하기 전에 원격 `main`에 앱 코드가 있는지부터 확인합니다.
