## 문제와 해결 방향

> **문제:** 학식 수요는 늘었지만, 학생들은 매번 학교 홈페이지 → 학식 아이콘 → 주차 → 요일별 메뉴까지 여러 단계를 거쳐야 했다.
>
> **해결:** 학식 메뉴를 크롤러로 수집해 MySQL에 저장하고, 메뉴와 별점·리뷰를 한 페이지에서 보여줬다.

## 내 역할과 핵심 기여

- **학식 크롤링** — 학교 홈페이지의 주차·요일별 메뉴를 수집해 MySQL `menu_tb`에 저장했다. 크롤러는 수동으로 실행했다
- **메뉴 화면** — 날짜로 메뉴를 조회해 Thymeleaf 페이지로 렌더링하고, 메뉴마다 좋아요·리뷰 버튼을 달았다
- **메뉴 리뷰** — 별점(`reviewRate`)과 리뷰 글(`reviewContent`)을 남기는 `MenuReview`, 좋아요 `MenuLike`를 만들고 메뉴별 리뷰 수와 평균 별점을 조회했다
- **인증** — Spring Security와 JWT(`JwtTokenProvider`, `JwtAuthenticationFilter`, `SecurityConfig`)로 로그인 인증을 구성했다

화면의 CSS 깨짐과 반응형 디자인 수정(커밋 2개)은 다른 팀원이 담당했습니다.

## 아키텍처

**학교 홈페이지 → 크롤러 → MySQL 저장 → Spring Boot 조회 → Thymeleaf 렌더링 → 메뉴별 별점·리뷰**

- **계층 분리** — `controller`, `service`, `repository`, `entity`, `dto` 패키지로 Spring MVC의 책임을 나눴다
- **인증 분리** — JWT 발급·검증(`JwtTokenProvider`)과 요청 필터(`JwtAuthenticationFilter`), 보안 설정(`SecurityConfig`)을 `config` 패키지에 따로 뒀다
- **엔티티** — `Member`, `Menu`, `MenuReview`, `MenuLike`, `Board`를 JPA로 매핑했다
- **수집과 서비스 분리** — 메뉴 저장은 크롤러가 맡고, Spring Boot 서버는 `menu_tb`를 조회만 한다

## 주요 구현

1. **학식 크롤러** — 학교 홈페이지의 주차·요일별 메뉴를 수집해, 학생이 홈페이지 → 학식 아이콘 → 주차 → 요일 단계를 거치지 않게 했다
2. **저장과 렌더링** — 크롤링한 메뉴를 `menu_tb`에 저장하고, 날짜로 메뉴를 조회해 Thymeleaf로 한 화면에 보여줬다
3. **메뉴별 별점·리뷰** — 메뉴마다 별점과 리뷰 글을 남기고, 메뉴별 리뷰 수와 평균 별점을 조회하게 했다. 좋아요는 회원 + 메뉴 이름 unique 제약으로 한 사람이 같은 메뉴에 한 번만 누르게 했다
4. **인증과 데이터 관리** — Spring Security + JWT로 인증하고, JPA 엔티티로 회원·메뉴·리뷰·좋아요 데이터를 관리했다

## 회고

완성도는 아쉬웠지만, MVC, Spring Security, JWT, JPA, MySQL, Thymeleaf, 크롤러를 함께 다루며 **데이터를 수집하고 저장하고 보여주는 서버 흐름**을 처음으로 끝까지 구현한 프로젝트입니다. 크롤러를 다시 실행하면 같은 메뉴가 중복 저장됐고, 이 경험으로 Calainder에서는 고정 이벤트 ID로 중복을 설계 단계부터 막았습니다.

크롤러는 정해진 시간에 자동으로 돌리는 스케줄러가 없어 수동으로 실행했고, 실패했을 때 로그나 알림을 남기는 구조도 없었습니다. 카카오톡 아침 학식 알림은 문자·메시지 발송이 유료이거나 기업 계정 조건이 필요해 구현하지 못했고, 대안으로 이메일 알림을 검토하는 데서 멈췄습니다. 외부 발송 채널은 비용과 계정 조건을 기획 단계에서 먼저 확인해야 한다는 것을 배웠습니다. 학식 게시판도 코드는 있지만 완성하지 못했습니다.

이후 학교 학식이 푸드코트 형식으로 바뀌어 메뉴를 크롤링할 수 없게 되면서 크롤러는 멈췄고, DDING!은 서브 프로젝트로 남았습니다.

**다음 개선 방향**

- 메뉴 이름·날짜 기준으로 중복을 판단해, 이미 있는 메뉴는 갱신하는 구조로 바꾼다
- 크롤러를 정해진 시간에 자동 실행하고, 실패 시 로그와 관리자 알림을 남긴다
- 외부 발송 채널은 비용과 계정 조건을 먼저 확인한 뒤 이메일 알림부터 구현한다
